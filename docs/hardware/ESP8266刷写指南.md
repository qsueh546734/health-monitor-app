# ESP8266-01S 刷写指南（从零开始，不用转接板）

> 这份文档是**自包含**的：只看它就能把 ESP8266-01S 刷上自定义固件。
> 面向从未刷过 ESP8266 的人。预计耗时 1–2 小时（第一次），之后 5 分钟一次。

---

## 0. 先看这一条：本项目为什么必须刷固件

| 方案 | 一次性成本 | 持续成本 |
|---|---|---|
| **刷自定义固件**（本方案） | 约 1–2 小时（就是这份文档） | 极低：ESP 自己处理 WiFi + TCP，STM32 只管串口收发 |
| 不刷，用 AT 指令 | 0 | **高**：STM32 侧要写 AT 响应解析、超时重试、状态机 —— 是经典的坑王，且极难调试 |

**结论**：刷固件是一次性投资，换掉一整个持续性工程负担。

---

## 1. 两条路径，先选一条

### 🟢 路径 A：有 ESP8266 刷写器（推荐，最省事）

**如果你有专用的 ESP8266 刷写器 / 烧录座**（插槽式、自带 USB 口的那种）：

1. 把 ESP-01S **插进刷写器**（注意方向，天线朝外）
2. 插 USB 到电脑
3. Arduino IDE 直接点上传 —— **不需要手动接任何线，不需要管 GPIO0，不需要卡上电时机**

刷写器内部已经解决了三件事：稳定的 3.3V 供电、GPIO0/CH_PD/GPIO2 的电平、DTR/RTS 自动复位。

**路径 A 的用户：直接跳到 §4。**

> ⚠️ **但请务必读 §9** —— 把模块从刷写器上拔下来、插到 STM32 板上时，刷写器提供的稳定 3.3V **就没有了**，供电问题会原样回来。这是本项目剩下最可能翻车的一步。

### 🟡 路径 B：没有刷写器，用 USB-TTL 硬接

需要下表中带 🔴 的东西：

| 物品 | 说明 |
|---|---|
| ESP8266-01S 模块 | 8 个引脚 |
| **USB-TTL 串口模块** | **必须是 3.3V 电平**（CH340 / CP2102 等，带 3.3V/5V 跳线帽的要把跳线设到 **3.3V**） |
| **3.3V 稳压电源** | 🔴 **关键**：AMS1117-3.3 小板（几块钱），或你的独立电源的 3.3V 那一路 |
| 电解电容 100µF + 陶瓷电容 0.1µF | 🔴 **关键**：跨接在 ESP 的 VCC–GND 上 |
| 杜邦线若干 | 母对母 |
| 电脑 + Arduino IDE | 见 §4 |

**路径 B 必须读 §2 和 §3。** 三个 🔴 是这条路上唯一会让你卡住的地方。

## 2. ⚠️ 先确认你的 USB-TTL 是 3.3V

**这一步不能跳。** 5V 电平会烧掉 ESP8266。

1. 如果模块上有 **5V/3.3V 跳线帽**：拔下来插到 **3.3V** 一侧
2. 上电后，用万用表量 **TX 引脚对 GND 的电压**（空闲时）：
   - 约 **3.3V** → 可以用 ✅
   - 约 **5V** → ❌ **不要接**，换模块或加电平转换

---

## 3. 接线（8 个脚，一个都不能错）

### 3.1 下载模式（要刷固件时）

| ESP-01S | 接到 | 说明 |
|---|---|---|
| **VCC** | **3.3V 稳压电源正极** | 🔴 不是 USB-TTL 的 3.3V（见 §3.3） |
| **GND** | 电源负极 **且** USB-TTL 的 GND | **必须共地** |
| **CH_PD**（EN） | **3.3V** | 🔴 不拉高芯片根本不启动 —— 最常见的"刷不进去"原因 |
| **RST** | 3.3V（或悬空） | 悬空通常也行 |
| **GPIO0** | **GND** | 🔴 这就是"进入下载模式"的开关 |
| **GPIO2** | **3.3V 或悬空** | 🔴 **不能接 GND**，否则启动失败 |
| **TX** | USB-TTL 的 **RX** | 交叉 |
| **RX** | USB-TTL 的 **TX** | 交叉 |

### 3.2 运行模式（刷完之后接 STM32）

| 变化 | 说明 |
|---|---|
| **GPIO0** → 从 GND 改为**悬空**（或接 3.3V） | 退出下载模式 |
| 其余不变 | VCC / GND / CH_PD / GPIO2 保持 |

> **实操建议**：把 GPIO0 那根线做成"可插拔"的 —— 一根线插到 GND 就是下载模式，拔掉就是运行模式。每次刷写只动这一根线。

### 3.3 🔴 供电：本项目最大的坑

**ESP8266 发射瞬间电流可达 ~300mA**，而多数 USB-TTL 的 3.3V 引脚只能提供 50–100mA。

**症状**：刷写进度条走到一半失败、反复 `Failed to connect`、运行中随机重启、WiFi 连上一会儿就掉。

**正确接法**：

```
        ┌─────────────┐
        │ 5V 电源     │
        └──────┬──────┘
               │
        ┌──────▼──────────┐
        │ AMS1117-3.3 小板 │
        └──────┬──────────┘
               │ 3.3V
        ┌──────┴──────┐
        │ 100µF 电解   │   ← 这两个电容是关键
        │ 0.1µF 陶瓷   │
        └──────┬──────┘
               │
          ESP-01S VCC

  同时：USB-TTL 的 GND ── ESP 的 GND（共地，但 3.3V 不接）
```

**验证方法**：给 ESP 上电，用万用表量 VCC 对 GND，**在它启动/WiFi 工作的瞬间**观察最低电压：
- ≥ 3.0V → 供电合格 ✅
- 掉到 3.0V 以下 → 供电不足，加大电容或换更强的 3.3V 源 ❌

## 4. Arduino IDE 配置

### 4.1 安装 IDE

下载安装 [Arduino IDE](https://www.arduino.cc/en/software)（2.x 即可）。

### 4.2 添加 ESP8266 开发板支持

1. `文件` → `首选项` → 在 **附加开发板管理器网址** 里粘贴：
   ```
   http://arduino.esp8266.com/stable/package_esp8266com_index.json
   ```
2. `工具` → `开发板` → `开发板管理器` → 搜索 `esp8266` → 安装 **esp8266 by ESP8266 Community**

> ⚠️ **国内下载可能非常慢或失败**（开发板包要从 GitHub 拉几百 MB）。
> - 你的 v2rayN 开 **TUN 模式（全局代理）** 通常能解决
> - 或找 esp8266 的离线安装包（社区有整合包）
> - 这一步失败不影响硬件，只是要重试

### 4.3 上传参数（工具菜单）

| 项 | 值 |
|---|---|
| 开发板 | `Generic ESP8266 Module` |
| Flash Size | `1MB (FS:none OTA:~370KB)` |
| Upload Speed | `115200` |
| CPU Frequency | `80 MHz` |
| **Reset Method** | 见下 |

**关于 Reset Method**：ESP-01S 的排针上**没有 DTR/RTS**，所以 IDE 的自动复位（`ck`/`nodemcu`）对它无效。请**用 §5.2 的手动复位流程**，Reset Method 保持默认即可 —— 关键是你要在正确时机给 ESP 上电。

## 5. 刷写流程

### 5.1 第一步：先刷一个"眨眼"固件验证工具链

**不要一上来就刷正式固件。** 先用最简单的程序确认"接线 + 供电 + IDE + 驱动"这条链是通的。

新建一个空白项目，粘贴：

```cpp
// ESP8266-01S 工具链验证固件
void setup() {
  Serial.begin(115200);
  delay(200);
  Serial.println();
  Serial.println("=== ESP8266 BOOT OK ===");
  pinMode(2, OUTPUT);
  Serial.println("=== 如果看到这几行，刷写就成功了 ===");
}

void loop() {
  digitalWrite(2, LOW);    // 板载 LED（多数 ESP-01S 批次在 GPIO2，低电平点亮）
  delay(500);
  digitalWrite(2, HIGH);
  delay(500);
  Serial.println("alive");  // 每 0.5 秒打印一次，串口助手能看到就说明运行正常
}
```

> **判定标准以串口为准，不以 LED 为准** —— 不同批次的 ESP-01S 板载 LED 接的引脚不一样，看不到灯亮不代表失败。**串口能打印就说明成功了。**

### 5.2 手动进入下载模式并上传

顺序很重要：

1. **接线**（§3.1）：GPIO0 → GND，CH_PD → 3.3V，GPIO2 → 悬空/3.3V，TX/RX 交叉，共地
2. **此时先不给 VCC 上电**
3. Arduino IDE 里**点【上传】**（左上角 → 按钮）
4. **看到 IDE 底部出现 `Connecting........_____` 时，立刻给 ESP 上电**（接通 VCC）
5. 进度条开始走 → 等待完成，出现 `Hash of data verified.` 和 `Leaving... Hard resetting via RTS pin...` 就是成功了

> 第 4 步是关键：**ESP 必须在 GPIO0 为低电平时上电**，才会进入 bootloader。
> 如果你上电早了/晚了没连上，IDE 会报 `Failed to connect to ESP8266` —— **断电，重来一次第 3–4 步即可**，不是硬件坏了。

### 5.3 切到运行模式并验证

1. **断电**
2. **拔掉 GPIO0 接 GND 的那根线**（改为悬空或接 3.3V）
3. 重新上电
4. 打开 Arduino IDE 的 **串口监视器**（波特率 **115200**）
5. 应该看到：
   ```
   === ESP8266 BOOT OK ===
   === 如果看到这几行，刷写就成功了 ===
   alive
   alive
   alive
   ```

**看到 `alive` → 刷写工具链完全打通 ✅** 之后刷正式固件就只是重复 §5.2–5.3。

## 6. 故障排查表

| 现象 | 最可能的原因 | 怎么办 |
|---|---|---|
| `Failed to connect to ESP8266: Timed out waiting for packet header` | ① 上电时机不对 ② GPIO0 没接 GND ③ **供电不足** | 按顺序排查：确认 GPIO0 接地 → 重做 §5.2 第 3–4 步 → **量 VCC 电压、加电容** |
| 进度条走到百分之几就失败 | **供电不足**（最常见） | 加 100µF 电容；换独立 3.3V 源；**不要用 USB-TTL 的 3.3V 引脚** |
| 完全搜不到串口 / IDE 没有端口 | USB-TTL 驱动没装 | 装 CH340 或 CP2102 驱动 |
| 串口监视器全是乱码 | 波特率不对 | 改成 `115200`；确认上电前 GPIO0 已悬空（否则它还在下载模式） |
| 刷完运行，但一启动就重启 | **供电不足**或 GPIO2 被拉低 | 加电容；确认 GPIO2 悬空或接 3.3V |
| 刷了正式固件后连不上 WiFi | `$I` 帧内容 / STA 的 SSID 密码不对；或它在等 STA 的 10 秒超时 | 等 10 秒看是否切到 AP；用串口监视器看 ESP 打印的日志 |
| IDE 上传按钮灰色 | 没选对开发板 | 工具 → 开发板 → 确认选了 `Generic ESP8266 Module` |

**一句话总结**：刷写失败 90% 是**供电**，9% 是**上电时机**，1% 是别的。

## 7. 本项目正式固件要做什么（刷完工具链后）

正式固件的行为如下（不需要看别的文档）：

```
上电 → 初始化串口 115200
     → 尝试连配置好的 WiFi（STA），10 秒超时
     → 成功：打印并发送 $I,IP=<DHCP地址>,PORT=8266,MODE=STA
     → 失败：自开热点
            SSID   : HealthMon
            密码   : 12345678
            IP     : 192.168.4.1（固定）
            → 发送 $I,IP=192.168.4.1,PORT=8266,MODE=AP
     → 启动 TCP 服务器（端口 8266）
     → loop()：串口 ↔ TCP 双向透传，不阻塞
```

**刷写步骤和 §5 完全一样**，只是把代码换成正式固件。

## 8. 刷完之后：手机连上测试

1. 手机 WiFi 里连 **`HealthMon`**（密码 `12345678`）
2. 手机浏览器打开 `http://192.168.4.1:8266` —— 打不开是正常的（它不是 HTTP 服务器，是 TCP 服务器）
3. 用**网络调试助手**类 App（如「网络调试助手」「TCP Client」）：
   - 模式：**TCP Client**
   - 地址：`192.168.4.1`
   - 端口：`8266`
   - 点连接 → 若能连上，说明 TCP 通了 ✅
4. 在发送框里发 `$C,CMD=QUERY,*00` → 如果 STM32 已接好，应能收到一帧 `$D`

5. 🔴 **同时做这个关键测试**：连着 `HealthMon` 的时候，用手机浏览器打开 `https://www.baidu.com`
   - **能打开** → DeepSeek 功能可用 ✅
   - **打不开** → 需要在手机设置里开「始终使用移动数据」/「智能切换网络」，或接受 AI 功能只在有路由器时可用
   - 这个结果请告诉我，它直接影响 AI 分析的方案

## 9. 🔴 从刷写器搬到 STM32 板上（路径 A 用户的头号坑）

**你现在的成功是在刷写器上取得的 —— 刷写器自带一个稳定的 3.3V 稳压。**

把模块拔下来插到 STM32 板上时，那个稳压**就没有了**。ESP8266 发射瞬间仍要 ~300mA，而 STM32 板上的 3.3V（Blue Pill 上的 AMS1117、或 ST-Link 供的 3.3V）经常给不出这么多。

**症状**（很容易被误判成"固件有问题"）：

| 现象 | 真实原因 |
|---|---|
| 上电后串口能打印几行，然后重启 | 供电不足，掉压复位 |
| WiFi 连上几秒就掉、反复重连 | 同上，发射瞬间掉压 |
| TCP 连上了但很快断 | 同上 |
| 串口打印乱码 | 也可能是掉压，不一定是波特率 |

**正确做法**：

```
你的独立电源 5V ──► AMS1117-3.3 ──┬──► ESP8266 VCC
                                   │
                          100µF + 0.1µF 电容对地
                                   │
STM32 的 3.3V ──✗ 不要用它给 ESP 供电（除非确认能给 300mA）
STM32 GND ──────► ESP GND   （必须共地）
STM32 PA2(TX) ──► ESP RX
STM32 PA3(RX) ◄── ESP TX
```

**验证方法**（搬过去之后立刻做）：

1. ESP 单独上电，**先不接 STM32**
2. 手机连 `HealthMon`，同时用串口监视器看着 ESP
3. 连续跑 5 分钟，期间反复用手机收发数据
4. **如果出现任何一次重启/乱码 → 供电不足**，加大电容或换更强的 3.3V 源

**电平兼容**：ESP8266 和 STM32 都是 3.3V 逻辑，**TX/RX 直连即可，不需要电平转换** ✓
