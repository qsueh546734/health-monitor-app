# 验收清单

> 用法：装好 APK 之后从上往下走。**每一项都写清了"应该看到什么"和"不对时告诉我什么"。**
> 前四组不需要任何硬件（模拟器模式），第五组才需要 ESP + STM32。

---

## 第 0 组：安装

| # | 操作 | 应该看到 | 不对时告诉我 |
|---|---|---|---|
| 0.1 | 安装 APK | 桌面出现「健康监测」 | 安装被拦：什么提示？ |
| 0.2 | 打开 | 进入「主控」页，顶部有 6 个页面按钮 | 闪退：装 `adb logcat` 或截图 |
| 0.3 | 点各个页面按钮 | 页面能切换，无卡顿 | 哪一页空白/闪退 |

> APK 从哪来：Actions → 最新成功的 run → 底部 Artifacts → `app-debug-apk`。
> 手机上直接下载 artifact 需要登录 GitHub；嫌麻烦可以让我把 APK 取出来放进 OneDrive。

---

## 第 1 组：模拟器模式（**不需要任何硬件**）

> 设置页 → 点【切换模拟器模式】→ 回主控页

| # | 操作 | 应该看到 |
|---|---|---|
| 1.1 | 开模拟器，回主控页 | 五张卡片开始**每秒跳动**：体温 36.x、心率 80 上下、步数递增、水位缓慢变化 |
| 1.2 | 看血氧那张 | 显示 **`--`**（血氧 P2 前不做，固定无效值） |
| 1.3 | 看底部统计 | `已收 N 帧 / 丢 0 帧 / 错误行 0  [模拟器]`，N 每秒 +1 |
| 1.4 | 看水泵那行 | 「水泵：自动，当前停止」—— 水位高于下限时 |
| 1.5 | 等约 3 分钟 | 水位降到 20% 以下 → 水泵变「运行中」+ 水位卡片变橙色 |
| 1.6 | 看顶部状态 | 「模拟器模式」，绿色 |

**重点**：卡片数字**每一秒都在变**。如果不动，说明刷新时钟坏了 —— 立刻告诉我。

## 第 2 组：报警（仍然不需要硬件）

> 报警只能在**有真实触发条件**时验证。模拟器目前没有暴露"注入异常"的界面入口，
> 所以这一组暂时用一个替代办法验证：**改阈值让它必然触发**。

| # | 操作 | 应该看到 |
|---|---|---|
| 2.1 | 设置页 → 体温上限填 **`35.0`** → 点【下发】 | 提示「有数值超出范围，已自动限制：35.0 / …」 |
| 2.2 | 回主控页等几秒 | **弹窗**「体温异常」+ 体温卡片**变红** + **响一声** |
| 2.3 | 关掉弹窗，继续观察 30 秒 | **不再重复弹窗**（同类报警 30 秒节流） |
| 2.4 | 等 30 秒后 | 会再弹一次（条件仍然成立） |

**三管齐下必须都出现**：弹窗 + 标红 + 声音。少任何一个都告诉我。

> 声音要在手机没静音的前提下听。

## 第 3 组：历史曲线

| # | 操作 | 应该看到 |
|---|---|---|
| 3.1 | 模拟器跑够 2 分钟后 → 历史页 | 出现一条折线，能看到起伏 |
| 3.2 | 点【心率】 | 曲线切换成心率（Y 轴数值范围也变了） |
| 3.3 | 点【10 分钟】/【1 小时】/【全部】 | 底部文字随之变化，曲线范围变化 |
| 3.4 | 曲线左下角 | 显示「体温 (℃)  xx 点」 |

**重点**：曲线要能看出**趋势**，不是一条直线也不是一团乱麻。

## 第 4 组：DeepSeek 分析

> 需要 API key。设置页 → 粘贴 key → 【保存 API key】

| # | 操作 | 应该看到 |
|---|---|---|
| 4.1 | 没填 key 时进分析页 | 提示「还没有填写 DeepSeek API key」 |
| 4.2 | 填好 key，手机有网时进分析页 | 「正在分析…」→ 几秒后出现一段**中文健康建议** |
| 4.3 | 看右上角 | `token：提问 xxx / 回答 xxx` |
| 4.4 | 输入框问「我最近的心率正常吗」→ 发送 | 出现回答，且**记得上文** |
| 4.5 | **断开 WiFi 和数据**后进分析页 | 提示切网，**不转圈** |
| 4.6 | 填一个错的 key | 提示「API key 无效」，不是一堆英文报错 |

**4.5 是方案 C 的保底** —— 连着设备热点时没有外网，必须给出明确指引而不是干等。

## 第 5 组：真设备联调（**需要 ESP + STM32 就绪**）

### 5.1 连上设备

| # | 操作 | 应该看到 |
|---|---|---|
| 5.1.1 | 设备上电，确认 OLED 显示 IP 和数值 | — |
| 5.1.2 | 手机连 `HealthMon`（密码 `12345678`） | — |
| 5.1.3 | 连接页填 OLED 上的 IP + `8266` → 【连接】 | 状态变绿「已连接 192.168.x.x:8266」 |
| 5.1.4 | 回主控页 | 五张卡片开始跳动，底部统计**没有 [模拟器]** 标记 |
| 5.1.5 | 看底部「丢 N 帧」 | 应长期为 **0** 或极小 |

### 5.2 阈值下发与回读

| # | 操作 | 应该看到 |
|---|---|---|
| 5.2.1 | 设置页改体温上限 → 【下发】 | 状态变「已下发，等待设备确认…」，收到下一帧后变「**设备已确认**」 |
| 5.2.2 | 点【读取当前值】 | 三个输入框**被真实值回填** |

> 5.2.1 的「设备已确认」是**隐式 ACK** —— 靠设备回显的阈值判断，不是本地假装成功。
> 如果一直停在"等待设备确认"，说明设备没回显 → 告诉同学检查 `$D` 帧里有没有 `BTHI/HRHI/WLOW`。

### 5.3 报警（真触发）

| # | 操作 | 应该看到 |
|---|---|---|
| 5.3.1 | 用手捂住红外探头 | 设备蜂鸣器响 + App 弹窗 + 卡片标红 + App 响一声 |
| 5.3.2 | 松手，等体温回落 | 卡片恢复绿色，蜂鸣器停 |

### 5.4 水泵与开关

| # | 操作 | 应该看到 |
|---|---|---|
| 5.4.1 | 抽走一点水让水位低于下限 | 水泵自动启动；App 显示「自动，当前运行中」 |
| 5.4.2 | 点【手动关】 | 显示「手动·关」，水泵停 |
| 5.4.3 | 点【恢复自动】 | 回到「自动」 |
| 5.4.4 | **关掉设备上的拨动开关** | App 顶部变灰「**系统已停止**」，卡片全部置灰，**且不报警** |
| 5.4.5 | 再打开开关 | 卡片恢复跳动 |

**5.4.4 是关键**：必须和「链路断开」（红色「连接已断开」）区分开。

### 5.5 异常与恢复

| # | 操作 | 应该看到 |
|---|---|---|
| 5.5.1 | 拔掉 ESP 电源 | 3 秒内出现「已连接但设备没有数据」→ 随后「连接已断开」 |
| 5.5.2 | ESP 重新上电，点【连接】 | 能重新连上 |
| 5.5.3 | 拔掉某个传感器 | 对应卡片显示 **`--`**（**不是 0**，也不是旧值） |
| 5.5.4 | 连续跑 30 分钟 | 曲线仍能秒开；App 不卡、不闪退 |

## 第 6 组：WiFi 配置（可选，验证 ESP 的配网功能）

| # | 操作 | 应该看到 |
|---|---|---|
| 6.1 | 设置页填**手机热点**名和密码 → 【让设备连这个热点】 | 状态文字出现；**连接会短暂断开**（正常） |
| 6.2 | 观察 | `HealthMon` 消失 → 设备连上热点 |
| 6.3 | 从串口或 OLED 读设备新 IP | 形如 `192.168.43.x` |
| 6.4 | 连接页填新 IP → 【连接】 | 能连上 |
| 6.5 | 此时浏览器打开 `baidu.com` | **能打开**（这是方案 A 的核心价值） |

**6.5 打不开是已知情况** —— 那就是方案 C：分析时切到移动数据，数据不会丢。

## 出问题时的报告格式

告诉我这三样，定位最快：

1. **第几组第几项**
2. **实际看到了什么**（截图最好）
3. **预期是什么**

如果是闪退，手机连电脑跑一次 `adb logcat -d > log.txt`，把最后 50 行发我。

## 明确不在本次范围

| 不做 | 原因 |
|---|---|
| 血氧（SPO2） | MAX30102 算法风险高，已与你确认推后 |
| 退出 App 后仍收报警通知 | Android 后台限制严，已与你确认"打开时提醒即可" |
| 云同步 / 多用户隔离 | 本地单人使用 |
| iOS | 只做 Android |
| 历史数据导出 CSV | 有曲线后价值降低 |
