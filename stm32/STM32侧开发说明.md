## 1. 你在整个系统里的位置

```
 ┌──────────┐  USART2   ┌─────────────┐   WiFi    ┌────────────┐
 │  STM32   │ 115200bps │ ESP8266-01S │◄─────────►│  手机 App  │
 │（你负责） │◄─────────►│（已写好）   │   TCP     │（已完成）   │
 └────┬─────┘           └─────────────┘           └────────────┘
      │ I2C / ADC / GPIO
 GY-906 / MAX30102 / MPU6050 / WaterSensor
 TB6612+水泵 / 蜂鸣器 / LED / 拨动开关
```

**你只需要做好一件事：按协议在串口上收发数据。**

WiFi、TCP、手机连接、App 界面**全部不用你管** —— ESP8266 已经把串口和网络透传好了。

### 两个方向

| 方向 | 内容 |
|---|---|
| **你发出去** | 每秒一帧 `$D`（传感器数据 + 状态） |
| **你收进来** | App 下发的 `$C` 命令（改阈值、控水泵、查询） |
| 另外还会收到 | ESP 的 `$I` 帧（告诉你它连上了哪个网络、IP 多少）—— **只需要显示在 OLED 上，不要当命令处理** |

## 2. 硬件连接

| STM32 引脚 | 接到 ESP8266 | 说明 |
|---|---|---|
| **PA2（USART2_TX）** | ESP 的 **RX** | 115200 8N1 |
| **PA3（USART2_RX）** | ESP 的 **TX** | 115200 8N1 |
| **GND** | ESP 的 **GND** | **必须共地** |

**电平**：ESP8266 和 STM32 都是 3.3V 逻辑，**直连即可，不需要电平转换**。

> ⚠️ **供电不要从 STM32 板取 3.3V**。ESP8266 发射瞬间要 ~300mA，
> 从板载 LDO 取电会导致整机复位。它有自己的独立电源。

## 3. 通信协议（**核心**）

### 3.1 通用规则

| 规则 | 约定 |
|---|---|
| 编码 | ASCII 文本（人能直接读懂） |
| 一帧的开始 | `$` |
| 一帧的结束 | **`\n`（0x0A）**。**不要发 `\r\n`** |
| 字段分隔 | `,` |
| 键值分隔 | `=` |
| 校验位 | `,*` 后接两位十六进制 —— **本版本一律填 `*00`** |
| 小数 | **固定 1 位**，例如 `36.5` |
| **无效值** | 写 **`--`**，**绝对不要写 0** |
| 单帧长度 | **不超过 128 字节** |
| 发送频率 | **1 秒 1 帧** |

> **为什么无效值不能写 0**：App 会把 `0` 当真实测量值显示（"体温 0.0℃"），
> 而 `--` 会显示成"没读到"。这两件事对用户的意义完全不同。

### 3.2 你发出去的：数据帧 `$D`

**每秒一帧，格式如下（这是一整行，最后有换行符）：**

```
$D,SEQ=123,BT=36.5,HR=72,SPO2=--,STEPS=1234,WATER=68,PUMP=0,PMODE=2,SW=1,AL=0,BTHI=37.3,HRHI=100,WLOW=20,*00
```

| 字段 | 含义 | 单位 | 取值范围 | 备注 |
|---|---|---|---|---|
| `SEQ` | 帧序号，每帧 +1 | — | 0–65535，到 65535 后回 0 | uint16 |
| `BT` | 体温（GY-906） | ℃ | 30.0–45.0，读不到写 `--` | 1 位小数 |
| `HR` | 心率（MAX30102） | bpm | 30–220，读不到写 `--` | 整数 |
| `SPO2` | 血氧（MAX30102） | % | **本版本固定写 `--`** | 先不做 |
| `STEPS` | 累计步数（MPU6050） | 步 | 0–999999 | 只增不减 |
| `WATER` | 剩余水位 | % | 0–100 | |
| `PUMP` | 水泵**当前**状态 | — | 0=关 1=开 | 真实状态 |
| `PMODE` | 水泵**控制模式** | — | 0=手动关 1=手动开 **2=自动** | 上电默认 2 |
| `SW` | 拨动开关 | — | 1=系统运行 0=系统停止 | |
| `AL` | 报警位（见 §3.3） | — | 0–15 | |
| `BTHI` | 体温上限（当前设定值） | ℃ | 35.0–42.0 | **必须回显** |
| `HRHI` | 心率上限（当前设定值） | bpm | 60–180 | **必须回显** |
| `WLOW` | 水位下限（当前设定值） | % | 0–100 | **必须回显** |

**最后的 `,*00` 是校验位占位，本版本固定写 `00`。**

#### ⭐ 三个"必须回显"的阈值

`BTHI` / `HRHI` / `WLOW` 必须在**每一帧**里带上当前实际生效的阈值。

**原因**：手机 App 判断"我下发的命令生效了没有"，靠的就是看下一帧里这三个值有没有变成新的。
这叫**隐式 ACK** —— 不需要额外的应答帧，但**你必须回显**，否则 App 会一直显示"等待设备确认"。

#### `SW=0`（拨动开关关掉）时的特殊格式

**仍然要每秒发一帧，但只带这几个字段：**

```
$D,SEQ=124,SW=0,AL=0,*00
```

其余字段**全部省略**。

> **为什么不能干脆停发**：如果关掉开关就完全停发，App 分不清「用户主动关机」和「WiFi 断了」——
> 前者正常、后者要报警。多发一行零成本的帧就能区分开。
> App 收到 `SW=0` 会显示"系统已停止"并把卡片置灰，**不会报警**。

### 3.3 `AL` 报警位

| 位 | 值 | 含义 | 什么时候置位 |
|---|---|---|---|
| bit0 | `0x01` | 体温异常 | `BT > BTHI` |
| bit1 | `0x02` | 心率异常 | `HR > HRHI` |
| bit2 | `0x04` | 水位过低 | `WATER < WLOW` |
| bit3 | `0x08` | 传感器故障 | 任一路读取失败 |

多位同时成立就用**按位或**。例如体温和心率都超了 → `AL=3`。

**设备侧同时要做**：置位时蜂鸣器响 + LED 亮；恢复正常后清位并关掉。

### 3.4 你收进来的：命令帧 `$C`

**格式：**

```
$C,CMD=<命令名>[,参数=值...],*00
```

**四条命令：**

| 命令 | 参数 | 取值范围 | 你要做什么 |
|---|---|---|---|
| `TH` | `BTHI`,`HRHI`,`WLOW` | 体温 35.0–42.0<br>心率 60–180<br>水位 0–100 | 更新三个阈值并保存（掉电不丢更好） |
| `PUMP` | `MODE` | 0=手动关 1=手动开 2=自动 | 切换水泵控制模式 |
| `QUERY` | 无 | — | 立即补发一帧 `$D` |
| `CLRSTEPS` | 无 | — | 累计步数清零 |

**例子：**

```
$C,CMD=TH,BTHI=37.3,HRHI=100,WLOW=20,*00
$C,CMD=PUMP,MODE=2,*00
$C,CMD=QUERY,*00
$C,CMD=CLRSTEPS,*00
```

> **注意**：`WIFI` / `WIFIFORGET` / `WIFISTATUS` 这三条命令会被 ESP8266 **拦截**，
> **根本不会传到你这里**。你不需要处理它们。

### 3.5 你还会收到：ESP 状态帧 `$I`

ESP 会在联网状态变化时发一行 `$I`：

```
$I,IP=192.168.4.1,PORT=8266,MODE=AP,*00
$I,IP=192.168.43.137,PORT=8266,MODE=STA,*00
$I,IP=192.168.4.1,PORT=8266,MODE=AP,WIFI=FAIL,RSN=PWD,*00
```

**你只需要做一件事：把其中的 `IP=` 解析出来显示在 OLED 上。**

用户要靠这个 IP 在手机 App 里连设备 —— 因为 IP 是会变的，OLED 是唯一可靠的显示位置。

**不要**把它当成 App 的命令处理。

### 3.6 还有一类：`#` 开头的调试行

ESP 会往串口打一些以 `#` 开头的日志（例如 `#AP started`、`#client connected`）。

**你的解析器必须忽略所有不以 `$` 开头的行。** 这是硬要求 —— 否则会被这些日志干扰。

## 4. 必须实现的行为（**这几条是安全相关的**）

### 4.1 上电必须先回零

**上电时 `PMODE=2`（自动）、`PUMP=0`（关）** —— 不能一上电就抽水。

### 4.2 水泵要有回差

```
水位低于 WLOW       → 开泵
水位高于 WLOW + 10  → 关泵
```

**必须加这 10% 的回差。** 否则水位正好在阈值附近时，水泵会**反复启停**（每秒开关一次，继电器和泵都受不了）。

### 4.3 传感器读失败要发 `--`

不能发 0，也不能沿用上一次的值。

### 4.4 拨动开关消抖

`SW` 判读建议加 **20ms 软件消抖**，否则 App 上会看到状态反复跳。

### 4.5 中断里只进缓冲，不做解析

串口中断里只把字节塞进环形缓冲，**不要在中断里解析帧或调用 printf**。

## 6. 参考代码

同目录下两个文件可以直接拷进工程：

| 文件 | 作用 |
|---|---|
| `proto.h` | 接口声明 |
| `proto.c` | 帧组装 + 命令解析 + 串口收发 |

**用法**（在你的主循环里）：

```c
#include "proto.h"

int main(void) {
    /* ... 你的初始化 ... */
    Proto_Init();

    while (1) {
        /* 1. 收：把串口来的行交给解析器 */
        char line[PROTO_LINE_MAX];
        while (Proto_Poll(line, sizeof(line))) {
            if (line[0] == '$' && line[1] == 'I') {
                Proto_HandleInfoFrame(line);   /* ESP 的 $I：更新 OLED 上的 IP */
            } else if (line[0] == '$') {
                Proto_ParseCommand(line);      /* App 的 $C：改阈值/控泵 */
            }
            /* 不以 $ 开头的行（# 调试行）直接忽略 */
        }

        /* 2. 你的传感器与执行器 */
        sensors_update();
        pump_control();      /* 含 10% 回差 */
        alarm_update();      /* 蜂鸣器 + LED */

        /* 3. 发：每秒一帧 */
        Proto_Tick(毫秒计数);
    }
}
```

`Proto_Tick()` 内部会自己判断是否到 1 秒，到点就调你提供的取值接口组帧发出。

**你需要提供一个"取当前值"的回调**（见 `proto.h` 里的结构体），把你的传感器读数填进去。

## 7. 联调步骤

### 第 1 步：串口自测（**不用 ESP，不用手机**）

把 USART2 接到电脑的 USB-TTL，用串口助手（115200）看：

- 应该每秒收到一行 `$D,...`
- 手动发一行 `$C,CMD=TH,BTHI=37.5,HRHI=105,WLOW=25,*00` 进去
- 下一帧的 `BTHI` 应该变成 `37.5`

**这一步过了，协议就对了 80%。**

### 第 2 步：接上 ESP

- ESP 上电（它会自己开 `HealthMon` 热点或连已有 WiFi）
- 串口上应该能看到 ESP 发来的 `$I,IP=...,MODE=...`
- 把这行解析出来显示在 OLED 上

### 第 3 步：手机连上来

用手机连 `HealthMon`（密码 `12345678`），App 里填 OLED 显示的 IP，端口 `8266`。
App 主控页应该开始显示你的数据。

### 第 4 步：命令验证

在 App 设置页改体温上限并点【下发】。
**App 的状态应该从「已下发，等待设备确认…」变成「设备已确认」** ——
说明你的 `$D` 帧里正确回显了新的 `BTHI`。

## 8. 常见错误

| 现象 | 原因 |
|---|---|
| App 一直显示"设备无数据" | 没发帧，或发的行没有 `\n` 结尾 |
| App 收到但数值全是 `--` | 字段名拼错（大小写敏感：`BT` 不是 `bt`） |
| 温度显示 `--` | 发了 `0` 而不是 `--`；或者字段名对但值解析失败（比如发了 `36.666` 三位小数） |
| App 显示"等待设备确认"一直不变 | `$D` 里没有回显 `BTHI/HRHI/WLOW` |
| 拨动开关关掉后 App 说"连接已断开" | 关机时停发了，应该继续发 `$D,SEQ=n,SW=0,AL=0,*00` |
| 水泵反复启停 | 没加 10% 回差 |
| 数据偶尔乱 | 没有按 `\n` 分帧（TCP/串口是字节流，一帧可能被拆成多次读、也可能两帧粘在一起） |
| ESP 连不上手机热点 | 热点必须是 **2.4GHz**，且不能是 **WPA3** |
